# לוח פרויקטים — ניהול פרויקטים עם הרשאות

אפליקציה מלאה (React + Express + Postgres) לניהול פרויקטים אישיים, עם כניסת מנהל, אנשי צוות, והרשאה נפרדת לכל איש צוות בכל פרויקט: אין גישה / צפייה / עריכה.

בנוי לפי המפרט `מפרט-דשבורד-פרויקטים.md`, על בסיס ה-UX של הפרוטוטייפ `projects-dashboard.jsx` — אבל עם שרת אמיתי, בסיס נתונים, סיסמאות מוצפנות ואכיפת הרשאות בצד השרת. פרוס על Vercel.

---

## הרצה מקומית

```bash
npm run setup
```

צור `.env` לפי `.env.example` ומלא `DATABASE_URL` (מחרוזת החיבור מ-Neon) ו-`JWT_SECRET`. אחר כך:

```bash
npm run db:init
```
```bash
npm run dev
```

- שרת API: http://localhost:4000
- ממשק פיתוח (Vite): http://localhost:5173 ← **כאן נכנסים**

בהרצה הראשונה נוצר חשבון מנהל. הסיסמה היא זו שב-`ADMIN_PASSWORD`, ואם לא הוגדרה — `admin1234`, והשרת מדפיס על כך אזהרה. **יש להחליף אותה מיד** במסך «צוות והרשאות».

## פריסה ל-Vercel

### 1. בסיס נתונים
צור פרויקט Postgres חינמי ב-[Neon](https://neon.tech) (או Vercel Postgres) והעתק את **מחרוזת החיבור המאגדת (Pooled connection)** — זו שכוללת `-pooler` בשם המארח. היא הנכונה ל-serverless.

### 2. משתני סביבה בפרויקט ב-Vercel
תחת Settings ‹ Environment Variables, לכל הסביבות:

| שם | ערך |
|---|---|
| `DATABASE_URL` | מחרוזת החיבור המאגדת מ-Neon, כולל `?sslmode=require` |
| `JWT_SECRET` | מחרוזת אקראית: `node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"` |
| `ADMIN_PASSWORD` | סיסמת המנהל הראשונית שתבחר |

בלי `JWT_SECRET` השרת מסרב לעלות — בכוונה. מפתח שנוצר לבד בכל instance היה מנתק משתמשים באקראי.

### 3. פריסה
`vercel.json` כבר מוגדר: הקליינט נבנה ל-`client/dist` ומוגש מה-CDN, ו-`api/index.js` מריץ את אותה אפליקציית Express כפונקציית serverless שמטפלת ב-`/api/*`. אין מה להגדיר ידנית ב-Vercel מעבר לחיבור הריפו ולמשתני הסביבה.

הסכימה וחשבון המנהל נוצרים לבד בבקשה הראשונה שמגיעה לשרת (אידמפוטנטי, מוגן בנעילת advisory כדי ששני cold starts במקביל לא יתנגשו).

## אבטחה — מה נאכף בפועל

- **סיסמאות**: bcrypt (cost 12) לכל המשתמשים, כולל המנהל. אין סיסמה גלויה בשום מקום — לא ב-DB ולא ב-API.
- **Session**: JWT חתום בעוגיית `httpOnly` + `sameSite=lax` + `secure` בפריסה, תוקף 8 שעות.
- **ביטול sessions**: הטוקן נושא טביעת אצבע של ה-hash הנוכחי. שינוי סיסמה מבטל מיידית כל טוקן ישן; מחיקת משתמש מנתקת אותו בבקשה הבאה.
- **אכיפה בצד השרת בלבד**: כל route שנוגע בפרויקט שואל את `permissionFor(user, projectId)`. הקליינט לא נשאל ולא נסמך.
  - איש צוות ללא רשומת הרשאה מקבל `404` — לא `403` — כדי לא לחשוף שהפרויקט קיים.
  - איש צוות עם `edit` יכול לשנות תיאור / סטטוס / התקדמות. שינוי שם ומחיקה הם פעולות מנהל בלבד.
- **הגבלת קצב**: 5 ניסיונות כניסה כושלים בחלון של 15 דקות ← נעילה של 15 דקות (לפי IP, ולאיש צוות גם לפי שם). המונים יושבים בטבלה `login_attempts` ולא בזיכרון, כי על serverless כל בקשה עלולה לנחות ב-instance אחר.
- **הודעות שגיאה**: כשל כניסה מחזיר תמיד «סיסמה שגויה», בלי לרמוז אם השם קיים.
- **ולידציה**: סטטוס מתוך רשימה סגורה, התקדמות שלם 0–100, סיסמת מנהל ≥ 8 תווים, סיסמת איש צוות ≥ 6.

### נקודה שכדאי להכיר

`GET /api/auth/members` מחזיר שמות אנשי צוות (id + שם בלבד) ללא אימות, כי מסך הכניסה במפרט מבוסס על בחירת שם מרשימה. זה חושף את רשימת השמות למי שמגיע לכתובת. אם זה לא רצוי — יש להחליף את הבחירה בשדה שם משתמש חופשי ולמחוק את ה-endpoint.

## API

| Method | Path | מי מורשה |
|---|---|---|
| GET | `/api/auth/members` | כולם (id + שם בלבד) |
| POST | `/api/auth/admin-login` | כולם — `{ password }` |
| POST | `/api/auth/member-login` | כולם — `{ userId, password }` |
| POST | `/api/auth/logout` | כולם |
| GET | `/api/auth/me` | מחובר |
| GET | `/api/projects` | מחובר — מסונן להרשאות, כולל שדה `level` |
| POST | `/api/projects` | מנהל |
| PATCH | `/api/projects/:id` | מנהל, או איש צוות עם `edit` (ללא שינוי שם) |
| DELETE | `/api/projects/:id` | מנהל |
| GET | `/api/users` | מנהל — כולל מפת הרשאות |
| POST | `/api/users` | מנהל |
| DELETE | `/api/users/:id` | מנהל (לא ניתן למחוק מנהל) |
| PUT | `/api/permissions` | מנהל — `{ userId, projectId, level }`, `level: none/view/edit` |
| PUT | `/api/admin/password` | מנהל — `{ newPassword }` |

## החלטות מימוש

- **Postgres דרך `pg`** — לא SQLite: הדיסק של Vercel זמני, וקובץ DB היה נמחק בכל cold start. השאילתות תקניות, כך שכל Postgres מנוהל יתאים, לא רק Neon.
- **סכימה מוגדרת ב-`DB_SCHEMA`** — כל החיבורים מקבלים `search_path` לסכימה אחת. זה מה שמאפשר לבדיקות לרוץ בסכימה זמנית באותו בסיס נתונים בלי לגעת בנתונים אמיתיים.
- **שמירה אוטומטית עם השהיה** — הקלדה בתיאור או שינוי אחוז התקדמות מתעדכנים מיידית במסך ונשלחים לשרת אחרי 600ms, מאוחדים לבקשה אחת. שינוי סטטוס ושם נשלחים מיד. עריכה שממתינה נשלחת גם אם עוברים לשונית או יוצאים.
- **אין WebSockets** — לפי המפרט, רענון בטעינת עמוד מספיק.
- **הרשאות אופטימיות** — לחיצה על «צפייה»/«עריכה» מתעדכנת מיידית ומתגלגלת אחורה אם השרת דחה.

## שאלות שהיו פתוחות במפרט — מה נקבע כאן

| שאלה | ההחלטה |
|---|---|
| יותר ממנהל אחד? | הסכימה תומכת בכמה (`role='admin'`), הכניסה בודקת מול כל חשבונות המנהל. אין UI ליצירת מנהל נוסף — רק דרך `ADMIN_NAME`/`ADMIN_PASSWORD` בזריעה הראשונה. |
| Audit log? | לא מומש. `projects.updated_at` מתעדכן בכל שינוי; טבלת `project_events` תהיה תוספת נקייה כי כל הכתיבות עוברות דרך `routes/projects.js`. |
| התראות? | לא מומשו. |
| Deployment? | Vercel + Neon Postgres. |

## בדיקות

```bash
npm run test:smoke
```

- אם `DATABASE_URL` מוגדר — הבדיקה יוצרת לעצמה סכימה זמנית (`smoke_xxxxxxxx`) באותו בסיס נתונים ומוחקת אותה בסוף. נתונים אמיתיים לא נוגעים בה.
- אם לא — היא מרימה Postgres בזיכרון (PGlite) ומריצה מולו, בלי שום תלות חיצונית.
