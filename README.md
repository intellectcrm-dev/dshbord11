# לוח פרויקטים — ניהול פרויקטים עם הרשאות

אפליקציה מלאה (React + Node + SQLite) לניהול פרויקטים אישיים, עם כניסת מנהל, אנשי צוות, והרשאה נפרדת לכל איש צוות בכל פרויקט: אין גישה / צפייה / עריכה.

בנוי לפי המפרט `מפרט-דשבורד-פרויקטים.md`, על בסיס ה-UX של הפרוטוטייפ `projects-dashboard.jsx` — אבל עם שרת אמיתי, בסיס נתונים, סיסמאות מוצפנות ואכיפת הרשאות בצד השרת.

---

## הפעלה מהירה

```bash
npm run setup
npm run dev
```

- שרת API: http://localhost:4000
- ממשק פיתוח (Vite): http://localhost:5173 ← **כאן נכנסים**

בהרצה הראשונה נוצר חשבון מנהל והסיסמה הראשונית מודפסת לקונסולה של השרת (ברירת מחדל: `admin1234`).
**יש להחליף אותה מיד** במסך «צוות והרשאות».

### הרצה ב-production

```bash
npm run build
npm start
```

הבנייה יוצרת את `client/dist`, והשרת מגיש אותו מאותו origin (כך שעוגיית ה-session נשארת first-party). לפני הרצה ב-production יש להעתיק `.env.example` ל-`.env` ולמלא `JWT_SECRET` — בלעדיו השרת מסרב לעלות.

## מבנה הפרויקט

```
server/
  index.js              הרכבת האפליקציה, הגשת הקליינט הבנוי, טיפול בשגיאות
  db.js                 סכימה, migrations בעלייה, זריעת חשבון המנהל הראשון
  auth.js               hashing, JWT בעוגייה, middleware של הרשאות, הגבלת קצב
  routes/auth.js        כניסת מנהל / איש צוות, יציאה, מי מחובר
  routes/projects.js    CRUD לפרויקטים, מסונן ונאכף לפי הרשאות
  routes/users.js       ניהול אנשי צוות (מנהל בלבד)
  routes/permissions.js קביעת רמת הרשאה לזוג משתמש+פרויקט (מנהל בלבד)
  routes/admin.js       שינוי סיסמת מנהל
client/
  src/App.jsx           session, ניווט, שכבת שגיאות
  src/components/       Login, ProjectsView, TeamView
  src/api.js            כל קריאות ה-API במקום אחד
data/                   בסיס הנתונים (נוצר אוטומטית, לא נכנס ל-git)
```

## אבטחה — מה נאכף בפועל

- **סיסמאות**: bcrypt (cost 12) לכל המשתמשים, כולל המנהל. אין סיסמה גלויה בשום מקום — לא ב-DB ולא ב-API.
- **Session**: JWT חתום בעוגיית `httpOnly` + `sameSite=lax` (ו-`secure` ב-production), תוקף 8 שעות.
- **ביטול sessions**: הטוקן נושא טביעת אצבע של ה-hash הנוכחי. שינוי סיסמה מבטל מיידית כל טוקן ישן; מחיקת משתמש מנתקת אותו בבקשה הבאה.
- **אכיפה בצד השרת בלבד**: כל route שנוגע בפרויקט שואל את `permissionFor(user, projectId)`. הקליינט לא נשאל ולא נסמך.
  - איש צוות ללא רשומת הרשאה מקבל `404` — לא `403` — כדי לא לחשוף שהפרויקט קיים.
  - איש צוות עם `edit` יכול לשנות תיאור / סטטוס / התקדמות. שינוי שם ומחיקה הם פעולות מנהל בלבד.
- **הגבלת קצב**: 5 ניסיונות כניסה כושלים בחלון של 15 דקות ← נעילה של 15 דקות (לפי IP, ולאיש צוות גם לפי שם). המונים בזיכרון התהליך.
- **הודעות שגיאה**: כשל כניסה מחזיר תמיד «סיסמה שגויה», בלי לרמוז אם השם קיים.
- **ולידציה**: סטטוס מתוך רשימה סגורה, התקדמות שלם 0–100, סיסמת מנהל ≥ 8 תווים, סיסמת איש צוות ≥ 6.

### נקודה שכדאי להכיר

`GET /api/auth/members` מחזיר שמות אנשי צוות (id + שם בלבד) ללא אימות, כי מסך הכניסה במפרט מבוסס על בחירת שם מרשימה. זה חושף את רשימת השמות למי שמגיע לכתובת. אם זה לא רצוי — יש להחליף את הבחירה בשדה שם משתמש חופשי ולמחוק את ה-endpoint.

## API

| Method | Path | מי מורשה |
|---|---|---|
| GET | `/api/auth/members` | כולם (id + שם בלבד) |
| POST | `/api/auth/admin-login` | כולם — `{ password }` |
| POST | `/api/auth/member-login` | כולם — `{ userId, password }` |
| POST | `/api/auth/logout` | כולם |
| GET | `/api/auth/me` | מחובר |
| GET | `/api/projects` | מחובר — מסונן להרשאות, כולל שדה `level` |
| POST | `/api/projects` | מנהל |
| PATCH | `/api/projects/:id` | מנהל, או איש צוות עם `edit` (ללא שינוי שם) |
| DELETE | `/api/projects/:id` | מנהל |
| GET | `/api/users` | מנהל — כולל מפת הרשאות |
| POST | `/api/users` | מנהל |
| DELETE | `/api/users/:id` | מנהל (לא ניתן למחוק מנהל) |
| PUT | `/api/permissions` | מנהל — `{ userId, projectId, level }`, `level: none/view/edit` |
| PUT | `/api/admin/password` | מנהל — `{ newPassword }` |

## החלטות מימוש

- **SQLite דרך `node:sqlite`** — המודול המובנה של Node 22.5+. אין תלות native, אין שלב קומפילציה, הקובץ יושב ב-`data/dashboard.db`. מעבר ל-PostgreSQL, אם הנפח יגדל, נוגע רק ב-`db.js` ובשאילתות שב-`routes/`.
- **שמירה אוטומטית עם השהיה** — הקלדה בתיאור או שינוי אחוז התקדמות מתעדכנים מיידית במסך ונשלחים לשרת אחרי 600ms, מאוחדים לבקשה אחת. שינוי סטטוס ושם נשלחים מיד. עריכה שממתינה נשלחת גם אם עוברים לשונית או יוצאים.
- **אין WebSockets** — לפי המפרט, רענון בטעינת עמוד מספיק.
- **הרשאות אופטימיות** — לחיצה על «צפייה»/«עריכה» מתעדכנת מיידית ומתגלגלת אחורה אם השרת דחה.

## שאלות שהיו פתוחות במפרט — מה נקבע כאן

| שאלה | ההחלטה |
|---|---|
| יותר ממנהל אחד? | הסכימה תומכת בכמה (`role='admin'`), הכניסה בודקת מול כל חשבונות המנהל. אין UI ליצירת מנהל נוסף — רק דרך `ADMIN_NAME`/`ADMIN_PASSWORD` בזריעה הראשונה. |
| Audit log? | לא מומש. `projects.updated_at` מתעדכן בכל שינוי; טבלת `project_events` תהיה תוספת נקייה כי כל הכתיבות עוברות דרך `routes/projects.js`. |
| התראות? | לא מומשו. |
| Deployment? | לא נבחר. השרת עצמאי לחלוטין (קובץ DB מקומי) ומתאים ל-VPS/Render/Fly. פלטפורמות עם דיסק זמני (Vercel serverless) ידרשו מעבר ל-PostgreSQL. |
